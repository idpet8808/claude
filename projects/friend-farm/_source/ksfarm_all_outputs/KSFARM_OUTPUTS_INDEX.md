### 2-12. 작물 시세 (KAMIS OpenAPI 기반 · 농장 등록 작물 기준)
[DECISION] **KAMIS API 응답 그대로, 매핑 DB 안 만듦.** 도매 위주, 농장 등록 작물 기준(타사처럼 등록 작물만), 전체 보기·검색 제거(검색 아이콘도 뺌 — 등록 작물만 봄). [DECISION] 화면 구조는 **지원사업 패턴 차용**(농장 한 줄 + 큰 헤드라인 + 탭). 단, 탭이 **작물별**(오이/딸기) — 탭 누르면 그 작물의 그래프 + 단위/품종별 시세. [DECISION] 작물 추가 = **농장 작물 등록과 연결**(시세 전용 등록 X — 농장 작물이 시세·병해충 등 전체 기능 공유). 탭 끝 [+] / 빈 상태 CTA 둘 다 농장 작물 등록으로.

**[ANALYSIS] KAMIS API 검증 (spoqa/kamispy github 직접 확인):**
- `daily_sales_list`(최근일자 도·소매가격정보) — 한 호출에 **218개 품목 전체** 응답. 품목이 아니라 **"품목+품종+단위" 단위로 쪼개져 옴**(오이/백다다기/10kg, 오이/가시/10kg 각각 별도 객체). 그래서 작물명으로 클라이언트 필터링하면 단위/품종별 리스트가 자동 구성됨(매핑 DB 불필요).
- 확실한 필드: `product_class`(01소매/02도매), `category_name`(식량작물·채소류·과일류·축산물·수산물·특용작물), `product_name`/`item_name`(품목명), `unit`(단위 — 20kg/1kg/포기 등), `latest_date`, `date_price_dict`(**당일·1일전·1개월전·1년전 4점** — 그래프용), `direction_type`(1상승/0하락), `direction_value`(등락률%), `productno`(상세 키).
- `period_product_list`(일별 품목별, 기간 조회) — 시계열·시장별·등급별. 파라미터: date_range, item_category_code, item_code, kind_code, product_rank_code, country, **convert_kg**(Y=kg환산/N·생략=원본단위). `county_name`(지역), `market_name`(시장), `reg_date`, `price`.

- **⭐ 작물 마스터 데이터 + 외부코드 매핑** (이번 세션 중요하게 부각, 기획·개발 기반): 농장 작물 하나가 **NCPMS 작목코드·KAMIS 품목코드·재배가이드 콘텐츠**와 다 연결돼야 함(시세·병해충·가이드가 모두 농장 등록 작물 기준). NCPMS 작목(병해충 조사 대상)과 KAMIS 품목(시세 조사 대상)이 서로 다를 수 있음 → 작물 하나에 각 외부 코드를 매핑하는 마스터 테이블 필요. [DECISION 방향] **농장 작물 등록을 "자유 입력"이 아니라 "품목 선택형"으로**(KAMIS·NCPMS 기준 리스트에서 선택, 병해충 검색과 같은 검색·선택 패턴) → 매칭 100%, 빈칸 없음. 등록 정책(둘 다 있는 작물만 vs 자유 등록 후 매칭) 미정. **시세 별도 등록은 안 함**(농장 작물 = 시세 작물, 한 곳에서 관리). 이건 디자인이 아니라 데이터 구조 설계 — 한 번은 만들어야 하고 우회 불가.
- **작물 시세 후속**: ① **농장 작물 등록 화면**(품목 선택형) 미착수 — 시세 탭 끝 [+]·빈 상태 CTA가 가는 곳(`ksfarm_farm_mo_hybrid.html`). ② 시세 검색 재도입 여부 — `pricesearch` 보존 중이나 현재 진입로 없음. ③ 단위·품종별 카드는 표시용(화살표 없음) — 누르면 동작 없음, 상세 페이지 안 만들기로 함(그래프에서 추이 다 보여줌). ④ 데모 파일(`pricehome_empty_demo`·`pricesearch`) 🔶 처리 미정.
- **영농일지 후속**: ① **병해진단 연동** — 진단 화면 모두 완성됨. 결과→일지 작성 변형 화면(B 방식 자동 채움) 미착수(위 참조). 목록 일지 카드의 "병해진단 결과 연결" 배지는 진단 결과 저장 구조 만들면 실제 연결. ② **작업유형 작물별 맞춤** 미정 — 현재 공통 10개, 작물별(과수=전정·적과 등) 노출은 작물 마스터 매핑 후 가능. ③ 자재는 자유 텍스트(자재 DB 없음) — 추후 농약 안전사용기준 연동 시 DB 필요할 수 있음. ④ 달력 목록의 일지 데이터·생육 상태 집계는 백엔드 연동 필요(견적 검토 때 "생육률 등 집계 로직 별도" 지적된 부분).
