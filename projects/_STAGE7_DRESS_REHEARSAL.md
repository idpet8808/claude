# Stage 7 드레스 리허설 체크리스트 (사용자 실행)

하네스 MVP 구축 완료 후 사용자가 직접 실행해야 할 V1~V5 검증 시나리오.
이 파일은 드레스 리허설 완료 후 삭제해도 된다.

---

## V1. `/kickoff` 1회 완결 테스트

**실행 방법**:
```
/kickoff <가상고객사> <가상프로젝트> <PM이름>
```
예: `/kickoff TestCorp 채용관리시스템 신주한`

**합격 기준**:
- [ ] 팀장 Claude가 `AskUserQuestion`으로 **누락 입력(고객사·WHY·1차 사용자·성공 지표)**을 1회 묶어 질의
- [ ] 서비스기획자 호출 → `projects/<slug>/01-prd.md` 생성
- [ ] 자가 점검 PRD N/7 결과가 산출물 하단에 기록됨
- [ ] **통과율 ≥ 5/7 게이트** 통과 후 기술검토자 호출 진행
- [ ] 기술검토자 → `02-tech-review.md` 생성 (N/5)
- [ ] **통과율 ≥ 4/5 게이트** 통과 후 UX기획자 호출
- [ ] UX기획자 → `03-ux-spec.md` 생성 (N/4, 빈/에러/로딩 상태 포함)
- [ ] 노션관리자 → `API-post-page` 호출 시 **사용자 승인 프롬프트** 발생 (settings.json ask)
- [ ] 승인 후 노션 페이지 생성 + STATE.md에 `Notion Page ID` 반영
- [ ] 최종 보고 4블록 포맷 (CLAUDE.md §10) 준수
- [ ] **전체 흐름 5분 내 완료** (사용자 개입 3회 이하)

**실패 시 대응**:
- PRD 자가 점검 5/7 미만 → 자동 재작성 1회 시도
- 기술 스택 결정 갈등 → 팀장이 옵션 3가지로 사용자에게 에스컬레이션

## V2. `/status` 실행

**실행 방법**: `/status`

**합격 기준** (최초 실행 시):
- [ ] 활성 프로젝트 0건 → `_INDEX.md`에 "아직 등록된 신규 프로젝트 없음" 유지
- [ ] 사용자 응답: "활성 0건 / 종료 0건 / 자가 점검 미달 0건 / 7일 미갱신 0건" 형식

**V1 완료 후 실행 시**:
- [ ] `_INDEX.md` 표에 V1에서 만든 슬러그가 1행 추가됨
- [ ] 각 산출물의 자가 점검 통과율이 표에 표시됨 (예: `PRD 6/7, Tech 4/5, UX 4/4`)
- [ ] 7일 미갱신·자가 점검 미달 경고 섹션은 없음 (갓 만든 프로젝트라서)

## V3. PRD 자가 체크리스트 (V1 산출물 기준)

V1에서 생성된 `projects/<slug>/01-prd.md`를 열어 하단 `## 자가 점검` 섹션을 수동 검증.

**합격 기준**:
- [ ] 7개 항목이 체크박스로 명시되어 있음
- [ ] `통과율: N/7` 숫자가 기록되어 있음
- [ ] 7항목 중 **6개 이상이 `[x]`** (6/7 이상)
- [ ] 1차 사용자가 1명으로 구체적 (실패 예: "일반 사용자")
- [ ] Must 기능이 5개 이하
- [ ] 제외 범위(Won't) 섹션이 비어있지 않음
- [ ] 성공 지표가 측정 가능한 숫자 형태
- [ ] 시나리오에 실패 케이스 1개 이상 포함
- [ ] 오픈 이슈의 모든 행에 담당자·기한이 채워져 있음

## V4. `/sync-notion` 실행

**실행 방법**:
```
/sync-notion projects/<slug>/01-prd.md
```
(V1에서 만든 슬러그 사용)

**합격 기준**:
- [ ] 노션관리자가 호출됨
- [ ] STATE.md의 `Notion Page ID` 확인 → 기존 페이지면 `patch-block-children`, 없으면 옵션 3가지 제시
- [ ] `patch-block-children` 호출 시 **사용자 승인 프롬프트** 발생
- [ ] 승인 후 노션 페이지 본문에 블록이 추가됨
- [ ] 본문 **깨짐 없음** — 한글·이모지·인라인 코드·링크 정상 표시
- [ ] 고급 블록(표, 토글, 콜아웃) 없음 — paragraph + bulleted_list_item만
- [ ] 손실된 서식이 있으면 완료 보고에 "손실: <항목>" 형태로 명시
- [ ] STATE.md Decision Log에 "`<파일명>` 노션 동기화" 기록 추가

## V5. 새 세션 시작 시 SessionStart Hook 주입

**실행 방법**:
1. Claude Code 프로세스 종료
2. Claude Code 재시작 (또는 `/clear`)
3. 첫 메시지를 보내거나 빈 응답 유도

**합격 기준**:
- [ ] 세션 시작 직후 첫 시스템 컨텍스트에 `projects/_INDEX.md` 내용이 포함됨
- [ ] 팀장 Claude에게 "현재 활성 프로젝트?"라고 물었을 때 `_INDEX.md` 기반으로 즉답
- [ ] V1~V4 실행 후라면, 그 프로젝트가 응답에 반영됨

**추가 검증**: `.mcp.json` 파일 수정 시도 시 PreToolUse Hook이 차단하는지 (별도 세션에서 테스트 가능)

## 종합 합격 조건

V1~V5 **모두 통과** 시 MVP 합격. 한 개라도 실패하면 해당 Stage로 돌아가 수정.

### 예상 실패 지점

| 시나리오 | 예상 원인 | 대응 |
|---|---|---|
| V1이 서비스기획자 호출 단계에서 멈춤 | 에이전트 정의의 `tools` 필드에 필요한 도구 누락 | `.claude/agents/service-planner.md` 프론트매터 확인 |
| V1 PRD 자가 점검 5/7 미만 | 사용자 입력 부족 | 더 자세한 비즈니스 배경 제공 |
| V4 본문 깨짐 | 이모지·한글 인코딩 | 노션 API 요청 헤더에 UTF-8 확인 |
| V5 Hook 주입 안 됨 | `settings.json` 경로 또는 hook 구문 오류 | `python -m json.tool .claude/settings.json`로 JSON 유효성 재검증 |
| Hook에서 grep 에러 | Windows git-bash 환경 이슈 | hook command를 stderr로 리다이렉트해 출력 확인 |
