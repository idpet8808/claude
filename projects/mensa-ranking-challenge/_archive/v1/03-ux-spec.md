### S1. 온라인테스트 첫 페이지 — 랭킹 위젯

**사용자 목표**: 기존 온라인테스트 페이지 방문 중 랭킹 현황을 보고 챌린지에 관심을 가져 CTA를 클릭한다.

**진입 경로**:
- 직접 URL 접속 (`/`) — 기존 멘사 온라인테스트 첫 페이지
- 검색 엔진 유입 (SEO — SSR Next.js 위젯)
- 북마크·SNS 공유 링크

**영역 구성**:

| 영역 | 역할 | 포함 컴포넌트 |
|------|------|--------------|
| 기존 사이트 헤더 | 기존 멘사 사이트 GNB (변경 없음) | 기존 헤더 (위젯 비접촉) |
| 랭킹 위젯 삽입 영역 | 기존 첫 페이지에 독립 JS 번들(IIFE)로 삽입 | 랭킹 Top-5 리스트, 내 순위 한 줄 (로그인 시), "도전하기" CTA 버튼, 타임스탬프 ("N분 전 업데이트") |
| 기존 사이트 본문 | 기존 온라인테스트 콘텐츠 (변경 없음) | 기존 본문 (위젯 하단 배치) |

**기술 제약 반영**:
- 위젯은 기존 사이트 코드 최소 수정 — 독립 JS 번들(IIFE) 방식 삽입 (`02-tech-review.md §4 리스크 7`)
- 랭킹 데이터는 Redis 5분 TTL 캐시에서 조회 — "N분 전 업데이트" 타임스탬프 필수 표시 (실시간이 아님을 사용자에게 명시)
- SSR(Next.js)로 초기 랭킹 데이터 렌더링 → SEO 지원

**4가지 상태** (모두 필수):

#### 정상 상태
- 랭킹 위젯에 Top-5 회원 (닉네임 마스킹 처리 가능 — 오픈 이슈 UX-01) + 점수 표시
- 로그인 사용자: "내 순위: N위" 한 줄 추가 노출
- 비로그인 사용자: "순위를 확인하려면 로그인하세요" 안내 텍스트
- "도전하기" CTA 버튼 활성화
- 타임스탬프: "N분 전 업데이트" 표시

#### 빈 상태 (Empty)
- 챌린지 참여자가 아직 없을 때 (초기 서비스 런칭 직후)
- 위젯 영역: "아직 도전한 회원이 없습니다. 첫 번째로 도전해보세요!" + "도전하기" CTA
- Top-5 리스트 대신 빈 순위 자리에 "--" 플레이스홀더 표시

#### 에러 상태 (Error)
- Redis 캐시 또는 API 응답 실패 시
- 위젯 영역: "랭킹 데이터를 불러오지 못했습니다. 잠시 후 다시 시도해주세요." 안내
- "새로고침" 링크 제공
- "도전하기" CTA는 에러 상태에서도 유지 (챌린지 참여는 랭킹 데이터와 독립)
- 기존 사이트 본문에는 영향 없음 (위젯 영역만 에러 상태)

#### 로딩 상태 (Loading)
- 위젯 초기 로드 시 (IIFE 번들 실행 + API 호출 중)
- Top-5 리스트 영역: 스켈레톤 UI (5행 회색 막대)
- "도전하기" 버튼: 비활성 상태 (disabled) 또는 스켈레톤
- 로딩 완료 후 정상/빈/에러 상태로 전환

**인터랙션**:

| 트리거 | 동작 | 결과 상태 |
|--------|------|----------|
| 위젯 영역 진입 (페이지 로드) | IIFE 번들 실행 → Redis API 호출 | 로딩 → 정상 / 빈 / 에러 |
| "도전하기" CTA 클릭 (비로그인) | 로그인 페이지로 리디렉션 + returnUrl 파라미터 전달 | S2(로그인) |
| "도전하기" CTA 클릭 (로그인) | 챌린지 목록 페이지로 이동 | S3(챌린지 목록) |
| "새로고침" 클릭 (에러 상태) | API 재호출 | 로딩 → 정상 / 빈 / 에러 |

### S2. 로그인

**사용자 목표**: 기존 멘사 회원 계정으로 로그인하여 챌린지 참여 권한을 얻는다.

**진입 경로**:
- S1 "도전하기" CTA 클릭 (비로그인 상태)
- 챌린지 목록·상세·패스 상품 페이지에 비로그인으로 접근 시 자동 리디렉션
- 직접 URL 접속 (`/challenge/login`)

**기술 제약 반영 (F-5 조건부)**:
- **시나리오 A/B (연동 가능)**: 기존 멘사 회원 ID/PW 로그인 폼 표시. 세션 쿠키 또는 JWT 검증 후 랭킹챌린지 내부 user_id 매핑
- **시나리오 C (연동 불가 — 대안 경로)**: 소셜 로그인(네이버·카카오) 또는 이메일 신규 가입 버튼 추가 표시. PM 승인 후 활성화 (현재 오픈 이슈 TR-01)
- 어떤 시나리오에서도 "신규 회원이세요?" 안내 텍스트 + 기존 멘사 사이트 회원가입 링크 표시

**영역 구성**:

| 영역 | 역할 | 포함 컴포넌트 |
|------|------|--------------|
| 상단 로고/타이틀 | 서비스 브랜드 식별 | 멘사 랭킹챌린지 로고, 서브타이틀 |
| 로그인 폼 | 기존 멘사 계정 인증 | ID 입력, PW 입력, 로그인 버튼, 오류 메시지 영역 |
| 안내 영역 | 비회원 진입 안내 | "멘사 회원만 참여 가능", 기존 사이트 회원가입 링크 |
| 시나리오 C 대안 영역 | 연동 불가 시 대안 표시 (조건부 활성화) | 소셜 로그인 버튼 (비활성 기본, TR-01 확정 후 활성) |

**4가지 상태** (모두 필수):

#### 정상 상태
- ID/PW 입력 폼 활성화
- 로그인 버튼 활성화
- returnUrl 파라미터가 있으면 로그인 성공 후 해당 페이지로 복귀

#### 빈 상태 (Empty)
- 해당 없음 (로그인 폼은 항상 비어있는 상태로 시작)
- 폼 입력 전: 플레이스홀더 텍스트 ("멘사 아이디", "비밀번호") 표시
- ID/PW 미입력 상태에서 로그인 버튼 클릭 시: 인라인 필드 오류 ("아이디를 입력해주세요", "비밀번호를 입력해주세요")

#### 에러 상태 (Error)
- 인증 실패 (잘못된 ID/PW): "아이디 또는 비밀번호가 올바르지 않습니다." 인라인 메시지
- 기존 멘사 API 연동 오류 (네트워크/서버): "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요." + 재시도 버튼
- 계정 잠금 (연속 실패 — 기존 멘사 정책 따름): "계정이 잠금되었습니다. 멘사 고객센터에 문의해주세요." + 고객센터 링크
- 에러 상태에서도 폼은 입력 가능 유지

#### 로딩 상태 (Loading)
- 로그인 버튼 클릭 후 API 응답 대기 중
- 로그인 버튼: 스피너 + "로그인 중..." 텍스트로 교체
- 폼 전체 비활성화 (중복 제출 방지)
- 성공: returnUrl 또는 S3(챌린지 목록)으로 이동
- 실패: 에러 상태로 전환, 폼 재활성화

**인터랙션**:

| 트리거 | 동작 | 결과 상태 |
|--------|------|----------|
| 로그인 버튼 클릭 (정상 입력) | 기존 멘사 인증 API 호출 | 로딩 → 성공 시 S3(또는 returnUrl) |
| 로그인 버튼 클릭 (빈 입력) | 클라이언트 유효성 검사 | 빈 상태 (인라인 오류 표시) |
| 로그인 버튼 클릭 (잘못된 인증) | API 인증 실패 | 에러 상태 (인라인 오류 메시지) |
| 회원가입 링크 클릭 | 기존 멘사 사이트 회원가입 페이지로 이동 | 외부 이동 (새 탭) |

### S3. 챌린지 목록

**사용자 목표**: 참여할 챌린지를 탐색하고 선택한다. 현재 자신의 종합 랭킹과 각 챌린지별 점수를 파악한다.

**진입 경로**:
- S1 "도전하기" CTA 클릭 (로그인 상태)
- S2 로그인 성공 후 자동 이동 (returnUrl = `/challenge`)
- GNB "챌린지" 메뉴 클릭
- S5(결과 화면) "다른 챌린지 도전" CTA 클릭

**영역 구성**:

| 영역 | 역할 | 포함 컴포넌트 |
|------|------|--------------|
| GNB | 전역 네비게이션 | 로고, 챌린지·패스 메뉴, 내 랭킹 배지, 힌트·패스 잔여 수량, 로그아웃 |
| 내 현황 배너 | 로그인 사용자 개인 현황 | 종합 랭킹 순위, 보유 힌트 수, 보유 패스 수, "패스 구매" 링크 |
| 챌린지 카드 목록 | 챌린지 탐색 | 챌린지 카드 (콘텐츠명, 유형 태그, 난이도, 내 점수, 최고 점수, 도전 인원 수) |
| 랭킹 사이드바 | 종합 랭킹 Top-10 미리보기 | 순위·닉네임·점수, "전체 랭킹 보기" 링크 |
| 패스 구매 배너 | 유료 패스 상품 홍보 | "패스로 무제한 도전" 문구, S7 연결 CTA |

**4가지 상태** (모두 필수):

#### 정상 상태
- 챌린지 카드 5개 이상 표시 (현재 5종 콘텐츠)
- 내 현황 배너: 종합 랭킹 N위, 보유 힌트 N개, 보유 패스 N개
- 미도전 챌린지: "도전하기" 버튼
- 이미 도전한 챌린지: "재도전하기" 버튼 + 내 점수 표시
- 랭킹 사이드바: Top-10 정상 표시

#### 빈 상태 (Empty)
- 챌린지가 아직 없는 경우 (운영 초기 — 예외적 상황)
- "준비 중인 챌린지가 곧 공개됩니다." + 안내 이미지
- 내 현황 배너: 종합 랭킹 "--위", 힌트·패스 0개
- 랭킹 사이드바: S1 빈 상태와 동일 처리

#### 에러 상태 (Error)
- API 호출 실패 시
- "챌린지 목록을 불러오지 못했습니다." + "새로고침" 버튼
- 내 현황 배너 영역도 "--" 처리
- GNB는 에러 무관하게 정상 표시 유지

#### 로딩 상태 (Loading)
- 페이지 진입 시 API 호출 중
- 챌린지 카드 영역: 스켈레톤 카드 3~5개
- 내 현황 배너: 스켈레톤 (순위, 힌트, 패스 수량 부분)
- 랭킹 사이드바: 스켈레톤 10행

**인터랙션**:

| 트리거 | 동작 | 결과 상태 |
|--------|------|----------|
| 챌린지 카드 클릭 | 해당 챌린지 상세로 이동 | S4(챌린지 상세) |
| "패스 구매" / 배너 CTA 클릭 | 패스 상품 페이지로 이동 | S7(패스 상품) |
| "전체 랭킹 보기" 링크 클릭 | 랭킹 전체 목록 (S5 랭킹 탭 또는 별도 모달) | 랭킹 전체 뷰 |

### S4. 챌린지 상세 / 문제 풀이

**사용자 목표**: 선택한 챌린지의 문제를 풀고 정답을 제출한다. 필요 시 힌트나 패스를 구매하여 사용한다.

**진입 경로**:
- S3 챌린지 카드 클릭 (목록에서 선택)
- S5 결과 화면 "재도전" CTA 클릭

**영역 구성**:

| 영역 | 역할 | 포함 컴포넌트 |
|------|------|--------------|
| 챌린지 헤더 | 챌린지 정보 표시 | 챌린지명, 카테고리 태그, 난이도, 경과 시간 (선택적), GNB 힌트·패스 잔여 |
| 문제 영역 | 콘텐츠 유형별 인터랙티브 컴포넌트 렌더링 | 유형별 컴포넌트 (하단 S4-A~E 세부 명세 참조) |
| 액션 바 | 힌트·패스 구매 및 제출 | "힌트 구매" 버튼, "이 문항 패스" 버튼, "정답 제출" 버튼, 진행 상태 표시 |
| 규칙 안내 영역 | 챌린지 규칙 요약 | 풀이 규칙 텍스트 (접기/펼치기) |

**기술 제약 반영**:
- 11배수 스도쿠 + 아름다운 수열 → 전용 인터랙티브 React 컴포넌트 별도 개발 필요 (`02-tech-review.md §2 F-2`)
- 챌린지 진행 상태(session_state)는 서버 저장 — 결제 실패/페이지 이탈 후 복귀 시 복원 가능
- 채점은 서버사이드 검증 (클라이언트 정답 노출 방지)

**4가지 상태** (모두 필수):

#### 정상 상태
- 선택한 챌린지의 문제 정상 렌더링
- 콘텐츠 유형에 따른 인터랙티브 컴포넌트 활성화
- 힌트·패스 잔여 수량에 따라 버튼 활성/비활성
- "정답 제출" 버튼: 모든 입력 필드 채워진 경우 활성화 (입력 완료 전: 비활성 또는 "아직 미완성 칸이 있습니다" 안내)
- 이전 진행 상태가 있으면 session_state에서 복원 ("이전 진행 상태를 불러왔습니다" 토스트)

#### 빈 상태 (Empty)
- 입력 전 초기 상태 — 모든 입력 칸 비어있음
- 각 콘텐츠 유형별 플레이스홀더 또는 빈 칸 표시 (S4-A~E 세부 참조)
- "정답 제출" 버튼: 비활성화 (disabled)

#### 에러 상태 (Error)
- 챌린지 데이터 로드 실패: "문제를 불러오지 못했습니다." + "다시 시도" + "목록으로 돌아가기" 링크
- 정답 제출 실패 (서버 오류): "제출 중 오류가 발생했습니다. 진행 상태는 저장되어 있습니다." + 재제출 버튼
- 힌트·패스 구매 실패: S6(구매 모달) 내 에러 상태로 처리 (S4 문제 화면 영향 없음, 진행 상태 유지)
- 네트워크 단절: "인터넷 연결을 확인해주세요." 토스트 + 진행 상태 로컬 임시 보관 안내

#### 로딩 상태 (Loading)
- 챌린지 데이터 초기 로드: 문제 영역 스켈레톤 + 스피너
- 정답 제출 중: "제출 중..." 스피너, 제출 버튼 비활성화 (중복 제출 방지)
- 힌트 사용 후 힌트 내용 로드 중: 힌트 영역 스피너

**인터랙션**:

| 트리거 | 동작 | 결과 상태 |
|--------|------|----------|
| 입력 필드 값 변경 | 클라이언트 실시간 유효성 표시 (유형별 규칙) | 유효: 정상 / 무효: 인라인 오류 표시 |
| "힌트 구매" 버튼 클릭 | 구매 모달 오픈 | S6(구매 모달) 오버레이 |
| "이 문항 패스" 버튼 클릭 | 패스 아이템 1개 차감 + 해당 문항 스킵 처리 | 다음 문항으로 이동 (또는 패스 잔여 0 시 S6 오픈) |
| "정답 제출" 버튼 클릭 | 서버사이드 채점 API 호출 | 로딩 → 성공 시 S5(결과) / 실패 시 에러 상태 |
| 페이지 이탈 전 경고 | "진행 중인 챌린지가 있습니다. 나가면 현재까지 진행 상태는 저장됩니다." 확인 다이얼로그 | 확인: 이탈 / 취소: 풀이 계속 |

#### S4-A. 배수 수열 컴포넌트 (content_type: `sequence_fill`)

**인터랙션 구조**:
- 10칸 수평 선형 입력 배열 (문제 1), 하단에 두 번째 10칸 배열 (문제 2) 순서로 배치
- 고정 셀: 배경색 구분 (회색 또는 테두리 강조), 입력 불가 처리
- 입력 가능 셀: 클릭 시 포커스, 숫자 키보드 활성화
- 규칙 텍스트: 문제 상단 접기/펼치기 아코디언 ("첫 번째에서 세 번째까지의 세 자리 수는 소수이다" 등)
- 입력값 실시간 검증: 0~9 정수 범위 외 입력 불가 (클라이언트)
- Tab/방향키로 셀 간 이동 지원

**빈 상태**: 고정 셀 외 모든 칸 공백. 각 칸에 "_" 또는 빈 입력 박스로 표시.

**에러 상태 (입력 오류 시)**: 제출 시 서버에서 오류 반환 — "정답이 올바르지 않습니다. 다시 시도해보세요." 인라인 메시지. 잘못된 입력 칸은 빨간 테두리 강조.

#### S4-B. 11배수 스도쿠 컴포넌트 (content_type: `grid_puzzle`)

**인터랙션 구조**:
- 9×9 그리드 렌더링. 굵은 테두리로 3×3 블록 구분
- 변수 레이블 셀 (a/b/c): 레이블 텍스트 표시 + 입력 가능 (변수값 입력)
- 고정 숫자 셀: 배경 구분색, 입력 불가
- 빈 셀: 클릭 시 포커스, 숫자 키보드 (1~9만 허용)
- 변수 레이블 셀은 동일 레이블에 동일 값 자동 동기화 (a에 5 입력 시 모든 a 셀 동시 표시)
- 규칙 힌트: "먼저 스도쿠 한 줄에 들어가는 아홉 자리 수가 11의 배수인 경우를 찾아보세요" 접기/펼치기
- 그리드 셀 크기: 데스크톱 최소 44×44px, 모바일 반응형 축소 (최소 36×36px, 터치 영역 유지)

**빈 상태**: 고정 셀 외 모든 빈 칸.

**에러 상태 (입력 오류 시)**: 같은 행/열/블록에 중복 숫자 입력 시 해당 셀 빨간 테두리 실시간 표시 (스도쿠 기본 규칙 위반).

#### S4-C. 너는 바보입니다 컴포넌트 (content_type: `symbol_equation`)

**인터랙션 구조**:
- 문항 1: 한글 자모/모음 — 숫자 방정식 연립 식 이미지 렌더링 + 답 입력 필드 1개
- 문항 2: 알파벳 — 숫자 나눗셈 방정식 구조 이미지 렌더링 (두 케이스: 이전과 다른 숫자 배치) + 답 입력 필드
- 식 이미지 위에 오버레이로 빈 박스(□) 표시 — 빈 박스 위치 클릭 시 또는 별도 입력 필드에 숫자 입력
- 입력 타입: 자연수 정수만 허용
- 문항 구분: 번호 뱃지 (1, 2) 로 시각 구분

**빈 상태**: 빈 박스(□) 그대로 표시, 입력 필드 공백.

**에러 상태 (입력 오류 시)**: 정수 외 문자 입력 차단. 제출 후 틀렸을 경우 "정답이 올바르지 않습니다." 인라인 메시지.

#### S4-D. 아름다운 수열 컴포넌트 (content_type: `graph_fill`)

**인터랙션 구조**:
- 32칸 링 그래프 (원형 접힘 구조) SVG 또는 CSS Grid 렌더링
- 각 노드: 클릭 시 포커스, 숫자 입력 (1~32 자연수, 각 숫자 1회만 사용)
- 인접 노드 쌍 합이 제곱수 규칙: 인접 노드 입력값 조합이 제곱수가 아닌 경우 인접 연결선을 빨간색으로 실시간 표시 (클라이언트 규칙 검증)
- 이미 사용한 숫자 재입력 시 경고: "이미 사용된 숫자입니다."
- 노드 크기: 데스크톱 최소 44×44px. 모바일에서는 스크롤 가능 캔버스 또는 핀치-줌 지원 (오픈 이슈 UX-02 — 모바일 레이아웃 확정 필요)
- 규칙 설명: "서로 연결된 두 수의 합이 제곱수가 돼야 합니다." 상단 안내 텍스트

**빈 상태**: 모든 32개 노드 공백 (빈 박스).

**에러 상태 (입력 오류 시)**: 인접 규칙 위반 시 연결선 빨간색. 중복 숫자 입력 시 인라인 경고.

#### S4-E. 아 치킨먹고싶다 컴포넌트 (content_type: `meta_quiz`)

**인터랙션 구조**:
- 10문항 자기참조 연립 퀴즈 목록 렌더링 (번호 + 문항 텍스트)
- 각 문항 우측 또는 하단에 자연수 입력 필드 1개
- 채점 기준 안내: "10문항 모두 정답 시 100점, 하나라도 틀리면 0점" 상단 명시
- 점수 기준표 (정답 개수 / 최종 점수) 접기/펼치기로 제공
- 7번 문항: "만약 000으로 끝나지 않는다면 시험을 포기하시오." — 포기 버튼 별도 표시 (클릭 시 "포기하면 0점 처리됩니다. 계속하시겠습니까?" 확인 다이얼로그)

**빈 상태**: 10개 입력 필드 모두 공백.

**에러 상태 (입력 오류 시)**: 자연수 외 입력 차단. 제출 후 0점 처리 시 "모든 문항이 정답이어야 100점입니다." 안내.

### S5. 챌린지 결과 / 랭킹 반영

**사용자 목표**: 제출한 챌린지의 점수와 현재 랭킹 순위를 확인한다. 재도전 또는 다른 챌린지로 이동한다.

**진입 경로**:
- S4 "정답 제출" 성공 후 서버 채점 완료 시 자동 이동

**영역 구성**:

| 영역 | 역할 | 포함 컴포넌트 |
|------|------|--------------|
| 결과 카드 | 챌린지 결과 요약 | 챌린지명, 획득 점수, 힌트/패스 사용 여부, 완료 시간 |
| 랭킹 반영 영역 | 현재 랭킹 순위 표시 | 이전 순위 → 현재 순위 변화 표시 (예: "↑ 3위 상승"), 종합 랭킹 N위 |
| 랭킹 미리보기 | 주변 순위 컨텍스트 | 내 위아래 3~5명 순위 표 (나는 강조 표시) |
| 액션 영역 | 후속 행동 유도 | "재도전하기" CTA, "다른 챌린지 보기" CTA, "패스 구매하기" 링크 (패스 잔여 0시 강조) |

**기술 제약 반영**:
- 랭킹은 Redis Sorted Set 기반 — 제출 즉시 Redis 갱신 → 결과 페이지에서 현재 순위 조회 가능 (5분 배치 캐시와 별개로 제출 시점 순위 즉시 계산)
- 온라인테스트 첫 페이지 위젯(S1)의 랭킹 반영은 최대 5분 지연 → 결과 페이지에 "랭킹은 최대 5분 내 첫 페이지에 반영됩니다." 안내 문구

**4가지 상태** (모두 필수):

#### 정상 상태
- 점수 카드 정상 표시 (100점 또는 0점 — 콘텐츠 유형별)
- 랭킹 순위 변화 애니메이션 (이전 → 현재 순위 트랜지션)
- 재도전 및 다른 챌린지 CTA 활성화

#### 빈 상태 (Empty)
- 이 화면에서 "빈 상태" = 첫 도전 (이전 순위 없음)
- "처음 도전하셨군요! 현재 순위: N위" 안내 텍스트
- 이전 순위 표시 없이 현재 순위만 표시

#### 에러 상태 (Error)
- 채점 결과 조회 실패: "결과를 불러오지 못했습니다. 답안은 저장되었습니다. 잠시 후 다시 시도해주세요." + "새로고침" 버튼
- 랭킹 조회 실패 (채점은 성공): 점수 카드는 정상 표시, 랭킹 영역만 "--위 (랭킹 데이터 준비 중)" 처리

#### 로딩 상태 (Loading)
- S4에서 제출 후 채점 서버 응답 대기 중 (S4 로딩과 연속)
- 결과 페이지 진입 후 랭킹 데이터 로딩: 랭킹 영역 스켈레톤
- 점수 카드: 스켈레톤 (채점 완료 전)

**인터랙션**:

| 트리거 | 동작 | 결과 상태 |
|--------|------|----------|
| "재도전하기" 클릭 | 동일 챌린지 초기화 후 재시작 | S4(챌린지 상세 — 초기 상태) |
| "다른 챌린지 보기" 클릭 | 챌린지 목록으로 이동 | S3(챌린지 목록) |
| "패스 구매하기" 클릭 | 패스 상품 페이지로 이동 | S7(패스 상품) |

### S6. 힌트·패스 구매 모달

**사용자 목표**: 챌린지 진행 중 힌트 또는 패스 아이템을 개별 구매하여 사용한다.

**진입 경로**:
- S4 "힌트 구매" 버튼 클릭 (힌트 잔여 0 또는 추가 구매 희망)
- S4 "이 문항 패스" 버튼 클릭 (패스 잔여 0)
- GNB 힌트/패스 잔여 클릭 (잔여 0 시)

**형태**: S4(챌린지 풀이 화면) 위에 오버레이 모달. S4 배경은 반투명 처리하되 진행 상태 유지.

**영역 구성**:

| 영역 | 역할 | 포함 컴포넌트 |
|------|------|--------------|
| 모달 헤더 | 구매 목적 명시 | 제목 ("힌트 구매" / "패스 구매"), 닫기(X) 버튼 |
| 상품 선택 | 구매 수량/상품 선택 | 힌트 1개 / 3개 / 5개 선택 라디오 또는 카드. 각 가격 표시 |
| 결제 수단 | 토스페이먼츠 위젯 | 카드·간편결제 선택 (토스페이먼츠 Payment Widget) |
| 결제 버튼 | 결제 실행 | "N원 결제하기" 버튼 |
| 하단 안내 | 패스 상품 유도 | "패스 상품으로 더 저렴하게 이용하세요" + S7 링크 |

**기술 제약 반영**:
- 결제 실패 시 S4 진행 상태 유지 필수 (`02-tech-review.md §2 F-3`, `01-prd.md §5 시나리오 2-B`)
- 결제 고유 주문번호(order_uuid) 생성 — 중복 결제 방지
- 결제 성공 후 아이템 지급 확인 후 모달 닫기

**4가지 상태** (모두 필수):

#### 정상 상태
- 상품 카드 정상 표시 (힌트/패스 종류·가격)
- 토스페이먼츠 Payment Widget 정상 로드
- "결제하기" 버튼 활성화
- 구매 완료: "힌트가 지급되었습니다. 이제 힌트를 사용해보세요!" 토스트 + 모달 자동 닫기

#### 빈 상태 (Empty)
- 이 모달에서는 해당 없음 (항상 상품 목록이 있음)
- 예외: 상품 목록 API 오류 시 에러 상태로 처리

#### 에러 상태 (Error)
- 결제 실패 (카드 한도 초과, 잔액 부족): "결제에 실패했습니다: [PG사 오류 메시지]." + "다른 결제 수단으로 시도" 버튼
- 결제 실패 (네트워크 오류): "결제 중 오류가 발생했습니다. 진행 중인 챌린지는 영향 없습니다." + 재시도 버튼
- 아이템 지급 확인 실패 (결제는 성공): "결제는 완료되었으나 아이템 지급 중 문제가 생겼습니다. 관리자에게 문의해주세요." + 고객센터 링크
- 에러 상태에서 "닫기" 클릭 시: S4 진행 상태 유지 확인

#### 로딩 상태 (Loading)
- 모달 오픈 시 상품 목록 + 토스페이먼츠 위젯 로딩: 스피너
- "결제하기" 버튼 클릭 후 결제 처리 중: 버튼 "결제 중..." 스피너, 버튼 비활성화
- 결제 성공 후 아이템 지급 중: "아이템 지급 중..." 표시

**인터랙션**:

| 트리거 | 동작 | 결과 상태 |
|--------|------|----------|
| 상품 카드/라디오 선택 | 가격 및 결제 버튼 금액 업데이트 | 정상 |
| "N원 결제하기" 클릭 | 토스페이먼츠 결제 처리 | 로딩 → 성공: 아이템 지급 + 모달 닫기 / 실패: 에러 상태 |
| 닫기(X) 클릭 | 모달 닫기 | S4(챌린지 상세) — 진행 상태 유지 |
| "패스 상품 보기" 링크 클릭 | S7 이동 (모달 닫기) | S7(패스 상품) |

### S7. 유료결제 패스 상품

**사용자 목표**: 힌트·패스 아이템을 묶음으로 저렴하게 구매한다.

**진입 경로**:
- S3 패스 구매 배너 클릭
- S6 모달 하단 "패스 상품 보기" 링크 클릭
- GNB 패스 메뉴 클릭
- S4 액션바 또는 S5 결과 화면 "패스 구매" 링크 클릭

**영역 구성**:

| 영역 | 역할 | 포함 컴포넌트 |
|------|------|--------------|
| 페이지 헤더 | 패스 상품 소개 | 타이틀, 혜택 요약 문구 |
| 패스 상품 카드 | 상품 선택 | 패스 종류별 카드 (포함 힌트 수, 패스 수, 가격, 혜택 배지) |
| 혜택 비교표 | 개별 구매 vs 패스 가격 비교 | 테이블 또는 리스트 형태 |
| 결제 영역 | 상품 선택 + 결제 실행 | 선택한 상품 요약, 토스페이먼츠 위젯, "N원 결제하기" 버튼 |
| 구독형 안내 영역 (조건부) | 구독형 선택 시 추가 안내 | "매월 자동결제됩니다. 언제든 해지 가능합니다." (TR-04 확정 후 활성화) |

**기술 제약 반영 (F-4 조건부)**:
- 현재 소진형(패스 번들) 기본 설계. 구독형 자동결제 UI는 TR-04 확정 전까지 숨김 처리 (feature flag)
- 구독형 선택 시 "자동결제 안내" 섹션이 추가 노출되는 구조 (PM 결정 대기)

**4가지 상태** (모두 필수):

#### 정상 상태
- 패스 상품 카드 정상 표시 (2~3종 예상)
- 가격·혜택 정상 표시
- 결제 CTA 활성화

#### 빈 상태 (Empty)
- 현재 판매 중인 패스 상품 없을 때 (운영 이슈)
- "현재 판매 중인 패스 상품이 없습니다. 곧 업데이트될 예정입니다." + 챌린지 목록 복귀 링크

#### 에러 상태 (Error)
- 상품 목록 로드 실패: "상품 정보를 불러오지 못했습니다." + "새로고침" 버튼
- 결제 실패: S6 에러 상태와 동일 처리 (동일 토스페이먼츠 결제 플로우)

#### 로딩 상태 (Loading)
- 상품 카드 로딩: 스켈레톤 카드 2~3개
- 결제 처리 중: "결제 중..." 스피너, 버튼 비활성화

**인터랙션**:

| 트리거 | 동작 | 결과 상태 |
|--------|------|----------|
| 패스 상품 카드 클릭 | 해당 상품 선택, 결제 영역 업데이트 | 정상 |
| "N원 결제하기" 클릭 | 토스페이먼츠 결제 처리 | 로딩 → 성공: 아이템 지급 + 완료 페이지 / 실패: 에러 상태 |
| 뒤로가기 / 이전 페이지 이동 | 이전 화면으로 복귀 | 이전 화면 |

### S8. 관리자 대시보드 (Should — F-6)

**분류**: Should 기능 (Must 격상 오픈 이슈 #3 / TR-05 대기 중)

**사용자 목표**: 멘사 운영 담당자가 챌린지 현황·결제 통계·랭킹 현황을 모니터링한다.

**진입 경로**:
- `/admin` 직접 접속 (관리자 전용 별도 인증 — 일반 회원 접근 불가)
- 관리자 인증: 별도 admin 계정 (기존 멘사 회원 DB와 별도 관리 또는 권한 레벨 분리 — 오픈 이슈 UX-03)

**영역 구성**:

| 영역 | 역할 | 포함 컴포넌트 |
|------|------|--------------|
| 관리자 GNB | 관리자 전용 네비게이션 | 대시보드, 챌린지 관리, 결제 관리, 회원 관리 메뉴 |
| 요약 지표 카드 | 핵심 지표 한눈에 확인 | 오늘 참여자 수, 이번 달 결제 건수/금액, 전체 랭킹 참여자 수 |
| 챌린지 현황 테이블 | 챌린지별 통계 | 챌린지명, 참여자 수, 평균 점수, 최고 점수 |
| 결제 통계 | 유료 아이템 결제 현황 | 일별 결제 건수, 상품별 판매량, 결제 실패율 |
| 랭킹 현황 | 전체 랭킹 관리 | Top-N 랭킹 목록, 수동 조정 기능 (오픈 이슈 UX-04) |

**4가지 상태** (모두 필수):

#### 정상 상태
- 모든 지표 카드 및 테이블 정상 표시
- 실시간 (또는 5분 갱신) 데이터 표시
- 결제 이력 수동 조회 가능

#### 빈 상태 (Empty)
- 서비스 런칭 초기 — 참여자·결제 데이터 없음
- 각 지표 카드: 0 표시, 테이블: "아직 데이터가 없습니다."

#### 에러 상태 (Error)
- 통계 API 실패: "데이터를 불러오지 못했습니다." + "새로고침" 버튼
- 권한 없는 접근: 관리자 로그인 페이지로 리디렉션

#### 로딩 상태 (Loading)
- 대시보드 진입 시: 지표 카드 스켈레톤, 테이블 스켈레톤 5행

**인터랙션**:

| 트리거 | 동작 | 결과 상태 |
|--------|------|----------|
| 날짜 필터 변경 | 선택 기간 통계 데이터 재조회 | 로딩 → 정상 |
| 챌린지 행 클릭 | 해당 챌린지 상세 통계 모달 | 모달 오버레이 |
| "결제 이력 다운로드" 버튼 클릭 | CSV 내보내기 | 파일 다운로드 |

## 5. 접근성·반응형 주요 결정

### 접근성 (WCAG AA)
- 색 대비: WCAG AA 기준 이상 (텍스트 4.5:1, UI 컴포넌트 3:1)
- 최소 터치 영역: 44×44px (그리드 셀 포함 — S4-B 11배수 스도쿠 그리드 셀, S4-D 아름다운 수열 노드)
- 키보드 네비게이션: 챌린지 입력 컴포넌트 Tab/방향키 이동 지원 (S4-A, S4-B)
- 스크린리더: aria-label 필수 — 그리드 셀 위치 ("3행 4열", "노드 7번"), 랭킹 순위 읽기
- 오류 메시지: role="alert" 또는 aria-live="polite"로 동적 메시지 전달

### 반응형 Breakpoints
- 모바일: ~767px (주요 사용 환경 — PRD §2 "온라인테스트 방문자" 모바일 비중 고려)
- 태블릿: 768px~1199px
- 데스크톱: 1200px+

### 주요 반응형 결정
- S1 랭킹 위젯: 모바일에서 Top-3으로 축소 표시, 데스크톱에서 Top-5
- S3 챌린지 목록: 모바일 1열, 태블릿 2열, 데스크톱 3열 카드 그리드
- S4-B 11배수 스도쿠 그리드: 모바일에서 셀 크기 축소 (최소 36×36px) + 좌우 스크롤 또는 화면 전체 활용
- S4-D 아름다운 수열 32칸 링 그래프: 모바일에서 스크롤 가능 뷰포트 또는 핀치-줌 지원 (오픈 이슈 UX-02)
- S6 구매 모달: 모바일에서 바텀 시트(bottom sheet) 형태로 전환
- S8 관리자 대시보드: 태블릿·데스크톱 전용 (모바일 지원은 오픈 이슈 UX-04)
