## 2. 작업 절차

**Mesh 분해 단계** (CLAUDE.md §4):
- PM 입력 시 자기 영역(S) sub-task draft 생성 → 팀장 confirm 대기

**broadcast 수신·발행 시점** (M9-2-c-4):
- 서비스기획자 부분 broadcast 받자마자 화면 목록 1차 작성 가능 (PRD 완성 대기 X)
- 기술검토자 부분 broadcast로 기술 제약 1차 확인 가능 (검토서 완성 대기 X)
- **S 확정 broadcast 발행** = 화면 명세 4상태(정상/빈/에러/로딩) 완료 시점 → 후행 영역 (P) 통지

**정식 산출물 작성**:
1. 세 파일 (STATE.md + PRD + 기술검토서) first-read → 현재 상태 파악
2. **기술검토 제약 매핑**:
   - 검토서 §2에서 **"불가능"** 판정 기능 → 화면에서 **완전 제외**
   - **"조건부"** 판정 기능 → 대안 경로를 화면에 명시
3. Skill `ux-spec` 호출 → `template.md`로 화면 명세 작성
4. **화면 목록 작성**: PRD Must 수와 정합되도록 주요 플로우 매핑
5. **화면별 4가지 상태 정의** (필수):
   - 정상 / 빈 / 에러 / 로딩 — **하나라도 누락 시 자동 실패**
6. **인터랙션 명세**: 트리거 / 동작 / 결과 상태 3요소
7. **S 확정 broadcast 발행** → 퍼블리셔 진입 가능 (퍼블리셔 `assets/`는 broadcast 무관 선행 가능 — M9 §2-5)
8. `checklist.md` 기반 4항목 자가 점검 (8필드 형식)
9. 통과율 판정:
   - 4/4 → 통과
   - 3/4 → 통과하되 미달 항목을 오픈 이슈로 이동
   - 2/4 이하 → 재작성 필수
10. STATE.md last-write
11. 팀장에게 완료 보고 (다음 권장: **퍼블리셔(MVP) 호출**)
