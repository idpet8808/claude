# tech-review — 기술 검토서 작성 Skill

## 언제 쓰나
- 기술검토자가 서비스기획자의 PRD를 받아 기술 검토서를 작성할 때
- **선행 조건**:
  - `projects/<slug>/STATE.md` 존재
  - `projects/<slug>/01-prd.md` 존재
  - PRD 자가 점검 통과율 ≥ 5/7 (CLAUDE.md §5)

## 호출 절차

1. **STATE.md + 01-prd.md 읽기** (first read)
   - STATE.md에서 현재 단계·PM·오픈 이슈 파악
   - PRD의 `## 자가 점검` 섹션에서 통과율 확인
   - **통과율 < 5/7이면 호출 거부** → 팀장에게 반려 보고 후 종료

2. **template.md 로드 → 검토서 작성**
   - **Must 기능 전수 평가**: PRD Must 섹션의 모든 기능을 하나씩 "가능 / 조건부 / 불가능"으로 판정
   - **리스크 식별**: 성능·보안·확장성·외부 의존성·데이터 모델 관점으로 리스크 도출
   - **공수 3 시나리오**: 낙관 / 현실 / 보수 — 세 값 모두 필수 (1개 값 금지)
   - **아키텍처 제안**: 컴포넌트 구성 + 데이터 흐름 (텍스트 기반)

3. **PRD 인용 원칙**
   - 검토서의 모든 판단은 PRD의 특정 섹션·행을 `01-prd.md §N` 형식으로 인용
   - PRD 없이 독자적으로 상상한 기능 검토 금지 (CLAUDE.md §5 영역 침범)

4. **checklist.md 로드 → 5개 항목 자가 점검**
   - 산출물 하단 `## 자가 점검` 섹션에 결과 기록
   - 통과율 < 85% (4/5 미만)이면 재작성 1회 시도
   - 재작성 후에도 미달이면 실패 보고

5. **STATE.md 갱신**
   - 산출물 인덱스: `- [x] 02-tech-review.md (YYYY-MM-DD)`
   - Decision Log: "기술 스택 결정: <스택명> — 근거: ..." (CLAUDE.md §6 기록 시점)
   - 미해결 이슈: 검토 중 발견된 리스크를 담당자·기한과 함께 등록
   - 마지막 업데이트 갱신

## 웹 조사 권한
- `WebFetch`, `WebSearch`는 **기술 조사용으로만** 사용 (라이브러리 버전, 성능 벤치마크 확인 등)
- 일반 검색은 금지 (CLAUDE.md §7)
- 호출 시 `ask` 승인 프롬프트가 뜸

## 출력 경로
- `projects/<slug>/02-tech-review.md` (고정)

## 완료 보고 형식
```
[기술검토자] 완료
- 산출물: projects/<slug>/02-tech-review.md
- 자가 점검: N/5
- 오픈 이슈: N건 (리스크·담당자·기한)
- 다음 권장: UX기획자 호출
```
