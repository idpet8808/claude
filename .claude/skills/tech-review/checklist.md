# 기술 검토서 자가 점검 체크리스트 (M11 v1 — M9 §10-2-2 정합)

기술검토자가 검토서 작성 직후 1차 게이트, 팀장 Claude가 UX기획자 호출 전 2차 게이트로 사용.

산출물 품질(§A 5항목) + cross-ref 정합(§B M11 v1) 두 layer.

통과 기준: **§A 4/5 이상 + §B error 0**.

---

## §A. 산출물 품질 자가 점검 (5항목, 통과 4/5)

### 1. Must 기능 전수 평가가 되어 있는가?
- [ ] 검토서 `2. Must 기능 전수 평가` 표의 행 수가 PRD `4. Must` 섹션 기능 수와 **정확히 일치**

### 2. 리스크별 완화책이 명시되어 있는가?
- [ ] `4. 리스크 분석` 표의 모든 리스크에 **완화책** + **담당자** 컬럼

### 3. 공수 3시나리오가 수치화되어 있는가?
- [ ] `6. 공수 산정`에 **낙관/현실/보수 세 값이 모두** 숫자(주 단위)

### 4. 외부 의존성이 확인되어 있는가?
- [ ] `5. 외부 의존성` 표의 모든 행에 **버전** + **라이선스** + **확인 여부(Y/N)**

### 5. 모든 판단에 PRD 섹션 인용이 있는가?
- [ ] Must 기능 평가의 `참조` 컬럼이 `01-prd.md §N` 형식

### 점수 해석 (§A)
- **5/5**: UX기획자 호출 가능
- **4/5**: 통과 — 미달 항목 오픈 이슈
- **3/5 이하**: 재작성 1회 (3회 연속 → PRD 자체 반려)

## §B. M11 v1 cross-ref 자가 점검 (M9 §10-2-2)

### 결과 형식 — 8필드 (M9 §9-4 F-7)

| # | 필드 | 값 |
|---|------|-----|
| 1 | type | self-check |
| 2 | timestamp | YYYY-MM-DD |
| 3 | owner | 기술검토자 |
| 4 | target | 02-tech-review.md / TR-NNN |
| 5 | 위반 항목 ID | F-* / M-* / U-* / H-* |
| 6 | result | pass / warning_only / error |
| 7 | 사유 | 1~3 문장 |
| 8 | evidence_ref | grep·라인·파일 |

### Part 1 — TR owner 자동 도출 (M9 line 1741)

- [ ] **F-1·F-2·F-3·F-4·F-5·F-6** (TR 한정): ID 정합 + 헤더 정합. TR-NNN 영역별 독립 시퀀스, 헤더 형식 `## TR-NNN (→ REQ-XXX, REQ-YYY)`. 결번 허용 (M9 §1-2-2)
- [ ] **F-8** (TR 한정): NA 사유 누락 검증
- [ ] **M-b·M-c·M-e** (TR 영역): 출처/끊김/NA 모순 없음. 모든 TR-NNN이 PRD REQ 참조 + 참조 REQ 실제 존재

### 전 owner 공통 (M9 line 1744)

- [ ] **H-1·H-2·H-5** NA 휴리스틱 (NA 시 적용, 없으면 N/A)

### Part 2 — 범용 U-1~U-5

- [ ] **U-1**: M9-5 자동 검증 통과 (TR 영역 error 0)
- [ ] **U-2**: Decision Log 변경 사항 반영 (기술 스택 / 리스크)
- [ ] **U-3**: 후행 영역(S·P) broadcast 발행 확인
- [ ] **U-4**: 노션 동기화 대상 결정 (PM 승인)
- [ ] **U-5**: 결과 `_broadcast.log` 8필드 기록

### 통과 기준 (§B)
- error 0 → 통과 / error 1+ → remediation 신설, Gate B 차단
