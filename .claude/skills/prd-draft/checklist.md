# PRD 자가 점검 체크리스트 (7항목)

이 체크리스트는 **서비스기획자** 에이전트가 PRD 작성 직후 1차 게이트로, **팀장 Claude**가 기술검토자 호출 전 2차 게이트로 사용한다.
통과 기준: **6/7 이상 (85%)**. 미달 시 재작성 또는 반려.

---

## 1. 1차 사용자가 1명으로 명확한가?
- [ ] 주 사용자가 구체적으로 1명으로 좁혀져 있음 (나이·직업·맥락 포함)
- **실패 예**: "일반 사용자", "B2B 고객" (너무 광범위)
- **통과 예**: "40대 중소기업 인사담당자"

## 2. WHY가 첫 문단에 존재하는가?
- [ ] PRD 섹션 1이 "왜 이걸 만드는가"로 시작하고, 비즈니스 배경·문제·기회가 2~4문단으로 서술됨
- **실패 예**: 기능 나열부터 시작
- **통과 예**: "기존 수작업 인증 프로세스로 월 40시간 소요 → 자동화로 80% 단축 목표"

## 3. Must 기능이 5개 이하인가?
- [ ] `4. 기능 범위`의 Must 섹션에 5개 이하
- **이유**: 6개 이상이면 범위 폭주 → 납기 리스크

## 4. 제외 범위(Won't)가 명시되어 있는가?
- [ ] 이번 스프린트에서 **하지 않을 것**이 최소 1개 이상 적혀 있음
- **이유**: Won't 없이는 "나중에 해달라"는 요청을 거절할 근거 없음

## 5. 성공 지표가 측정 가능한 형태인가?
- [ ] `3. 성공 지표` 표의 모든 항목에 **숫자 목표값** + **측정 방법**이 있음
- **실패 예**: "사용성 개선", "만족도 향상"
- **통과 예**: "월간 활성 사용자 500명 / GA4로 측정"

## 6. 시나리오에 실패 케이스가 1개 이상 있는가?
- [ ] `5. 주요 사용자 시나리오`에 정상 경로 외에 **실패/예외 경로** 시나리오가 최소 1개
- **이유**: 정상 경로만 있으면 UX기획자가 빈/에러 상태를 설계할 근거 없음

## 7. 오픈 이슈에 담당자·기한이 연결되어 있는가?
- [ ] `7. 오픈 이슈` 표의 모든 행에 **담당자** + **기한**이 채워져 있음
- **이유**: CLAUDE.md §6 "담당자·기한 없는 이슈는 등록 거부"

---

## 점수 해석
- **7/7**: 완벽 — 즉시 기술검토자 호출
- **6/7**: 통과 — 미달 1항목을 오픈 이슈로 이동 후 기술검토자 호출
- **5/7 이하**: 재작성 필수 — 미달 항목을 채워 재시도
- **3회 연속 5/7 이하**: CLAUDE.md §9에 따라 사용자에게 요구사항 재검토 요청
