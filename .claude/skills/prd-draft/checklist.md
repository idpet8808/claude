# PRD 자가 점검 체크리스트 (M11 v1 — M9 §10-2-2 정합)

본 체크리스트는 **서비스기획자** 에이전트가 PRD 작성 직후 1차 게이트, **팀장 Claude**가 기술검토자 호출 전 2차 게이트로 사용한다.

산출물 품질(§A 7항목) + cross-ref 정합(§B M11 v1) 두 layer로 검증.

통과 기준: **§A 6/7 이상 + §B error 0** (CLAUDE.md §6 게이트 정합).

---

## §A. 산출물 품질 자가 점검 (7항목, 통과 6/7)

### 1. 1차 사용자가 1명으로 명확한가?
- [ ] 주 사용자가 구체적으로 1명으로 좁혀져 있음 (나이·직업·맥락 포함)
- **실패 예**: "일반 사용자", "B2B 고객"
- **통과 예**: "40대 중소기업 인사담당자"

### 2. WHY가 첫 문단에 존재하는가?
- [ ] PRD 섹션 1이 "왜 이걸 만드는가"로 시작하고, 비즈니스 배경·문제·기회가 2~4문단으로 서술됨

### 3. Must 기능이 5개 이하인가?
- [ ] `4. 기능 범위`의 Must 섹션에 5개 이하
- **이유**: 6개 이상이면 범위 폭주 → 납기 리스크

### 4. 제외 범위(Won't)가 명시되어 있는가?
- [ ] 이번 스프린트에서 **하지 않을 것**이 최소 1개 이상

### 5. 성공 지표가 측정 가능한 형태인가?
- [ ] `3. 성공 지표`의 모든 항목에 **숫자 목표값** + **측정 방법**

### 6. 시나리오에 실패 케이스가 1개 이상 있는가?
- [ ] `5. 주요 사용자 시나리오`에 정상 경로 외에 **실패/예외 경로** 시나리오가 최소 1개

### 7. 오픈 이슈에 담당자·기한이 연결되어 있는가?
- [ ] `7. 오픈 이슈` 표의 모든 행에 **담당자** + **기한** (CLAUDE.md §7)

### 점수 해석 (§A)
- **7/7**: 즉시 기술검토자 호출
- **6/7**: 통과 — 미달 1항목을 오픈 이슈로 이동 후 호출
- **5/7 이하**: 재작성 1회 (3회 연속 미달 시 CLAUDE.md §10 재시도 한계)

## §B. M11 v1 cross-ref 자가 점검 (M9 §10-2-2)

### 결과 형식 — 8필드 (M9 §9-4 F-7 통합)

각 §B 항목 결과를 다음 8필드로 `_broadcast.log`에 type=`self-check`로 기록:

| # | 필드 | 의미 |
|---|------|------|
| 1 | `type` | `self-check` |
| 2 | `timestamp` | 시점 |
| 3 | `owner` | `서비스기획자` |
| 4 | `target` | `01-prd.md` |
| 5 | 위반 항목 ID | F-* / M-* / U-* / H-* |
| 6 | `result` | `pass` / `warning_only` / `error` |
| 7 | `사유` | 1~3 문장 |
| 8 | `evidence_ref` | grep·라인·파일 |

### Part 1 — REQ owner 자동 도출 (M9 line 1740)

- [ ] **F-1·F-2·F-3** (REQ 한정): ID 정합 — 영역별 독립 시퀀스 max(NNN)+1, 중복·재사용 없음. 결번은 허용 (M9 §1-2-2).
- [ ] **F-4·F-5·F-6** (REQ 한정): 헤더 정합 — `## REQ-NNN ({제목})` 형식 일치
- [ ] **F-8** (REQ 한정): NA 사유 누락 검증 (NA 항목 시 사유 1줄 강제)
- [ ] **M-a** (REQ 영역): orphan 없음 — PRD에 정의된 REQ가 후행 영역에서 미참조되지 않음
- [ ] **M-d** (REQ 영역): deprecated 참조 없음 — deprecated REQ를 active 영역이 참조하지 않음

### 전 owner 공통 (M9 line 1744)

- [ ] **H-1·H-2·H-5** NA 휴리스틱 — NA 항목 시 적용, 없으면 N/A 명시

### Part 2 — 범용 U-1~U-5 (M9 line 1748~1754)

- [ ] **U-1**: M9-5 자동 검증 통과 (`_broadcast.log` REQ 영역 error 0건)
- [ ] **U-2**: Decision Log 변경 사항 반영 (STATE.md 기록)
- [ ] **U-3**: 후행 영역(TR·S·P) broadcast 발행 확인
- [ ] **U-4**: 노션 동기화 대상 결정 (PM 승인 — `/sync-notion` 시점)
- [ ] **U-5**: 본 §B 결과를 `_broadcast.log`에 8필드 기록 (evidence)

### 통과 기준 (§B)
- error 0건 → 통과
- error 1건 이상 → remediation Task 신설, Gate B 차단 (M9 §10-2-3)
