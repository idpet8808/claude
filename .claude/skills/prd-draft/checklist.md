# PRD 자가 점검 체크리스트 (M16 — PI-001~PI-013·PI-018 정합)

본 체크리스트는 **서비스기획자** 에이전트가 PRD 작성 직후 1차 게이트, **팀장 Claude**가 후행 영역 *완성 산출물 사용 게이트* 진입 시 2차 게이트로 사용한다.

산출물 본질(§A 자동 실패 4건 + 통과율 7건) + cross-ref 정합(§B M11 v1 — 보존) 두 layer로 검증.

**통과 기준**: §A 자동 실패 0 위배 + 통과율 ≥ 6/7 + §B error 0 (CLAUDE.md §6-2 정합).

---

## §A. 산출물 본질 자가 점검 (M16 PI 정합)

### 자동 실패 조건 (4건 — 1건 위배 시 통과율 무관 즉시 재작성)

#### A-1. §0 PM 원본 보존 (PI-009 — 의도 SSoT)

- [ ] PRD §0 섹션이 *PM 원본 그대로* 보존됨
- [ ] PM 발화·사업계획서·RFP·인터뷰 메모·`AskUserQuestion` 응답이 *원문 그대로* (변환·삭제 0건)
- service-planner는 §0 *변환·삭제 금지* (영역 침범 — CLAUDE.md §9 안티 패턴)
- **실패 예**: PM 원본을 정형화 표현으로 변환하여 §0 입력
- **통과 예**: PM 원본 그대로 §0 삽입 + §A·§B는 *정형화*로 별도 작성
- **자동 실패 사유**: 의도 SSoT 손실 = 격차 6 근본 원인 (M16 진입 본질)

#### A-2. §B 16 필드 필수 13 채움 (PI-002 — 16 필드 양식 본질)

- [ ] §B 요구사항 카탈로그의 모든 항목이 *필수 13 필드* 채움
- **필수 13 필드**: 대분류 / 중분류 / 개발/패키지 / 구분 / 시스템명 / 업무영역명 / 요구사항 ID / 요구사항명 / 요구사항 설명 / 세부내용 및 요건 / 유형 / 업무 담당자 / 출처
- **NA 허용 3 필드**: 소분류 / 제약사항 및 전제조건(경계 사례 없으면 NA) / 기타사항
- **자동 실패 사유**: BN 표준 양식 본질. 필수 필드 누락 = 16 필드 카탈로그 부재

#### A-3. §B REQ ID 4 segment 정규식 정합 (PI-004 — ID 체계 본질)

- [ ] 모든 요구사항 ID가 정규식 `^REQ-[A-Z]{2,4}-\d{3}-\d{2}$` 정합
- **형식**: `REQ-{도메인 2~4글자}-{NNN}-{NN}` (예: `REQ-USR-001-01`)
- **자동 실패 사유**: ID 체계 본질. 정규식 위배 시 cross-ref 자동 검증 깨짐

#### A-4. §B 경계 사례 PRD 명시 (PI-011 — 격차 4 정정 핵심)

- [ ] 경계 사례 영역(SSO·결제·2FA·이미지 업로드 등)이 §B 16 필드로 *명시*되어 있음
- 명시 위치: *제약사항 및 전제조건* 필드 또는 별도 요구사항 등록
- **실패 예**: PRD에 결제·SSO 등 경계 사례 미명시 → 후행(TR·UX·P) 자율 결정 위임
- **자동 실패 사유**: 격차 4 (자율 결정 우회) 회귀 방지

---

### 통과율 산정 7항목 (6/7 이상 통과, 5/7 이하 재작성)

#### B-1. §A 비전 = WHY + 1차 사용자만 (KPI 0건) — PI-007·PI-008

- [ ] §A-1 WHY가 비즈니스 배경·문제·기회 2~4문단
- [ ] §A-2 1차 사용자가 1명으로 명확 (나이·직업·맥락 포함)
- [ ] KPI(성공 지표·측정 목표) 0건 — *제거* (PI-008)

#### B-2. §B 출처 = §0 PM 원본 인용 — PI-002·PI-009

- [ ] 모든 요구사항의 *출처* 필드가 §0 PM 원본 *인용 형식* (예: "§0-3 PM 메모 4단락")
- [ ] 추적성 보존 — 출처 인용 → §0 원본 연결 가능

#### B-3. §B 대분류·중분류·소분류 분류 — PI-002·PI-006

- [ ] 모든 요구사항의 *대분류* 필드 채움 (필수)
- [ ] *중분류* 채움 (선택 — NA 가능)
- [ ] *소분류* NA 허용
- [ ] 대분류 그룹화 §B-1·§B-2·... 적용 (PI-006)

#### B-4. §B 유형 (기능/비기능) — PI-002

- [ ] 모든 요구사항의 *유형* 필드가 "기능" 또는 "비기능"

#### B-5. §B 담당자 명시 — PI-002

- [ ] 모든 요구사항의 *업무 담당자* 필드 채움 (선택 — 서명 포함 가능)

#### B-6. §C 표준 패턴 형식 — PI-013 (NA 허용)

- [ ] §C 섹션이 표준 패턴 자율 결정 시 1줄 형식 (`(YYYY-MM-DD) 영역: default 결정`)
- [ ] ID 부여 0건 (PI-013 — *프로젝트 무관 관행*이므로 ID 미부여)
- [ ] NA 허용 — 자율 결정 발생 0건 시 §C 자체 N/A 명시

#### B-7. §D 오픈 이슈 담당자·기한 (M9·M13 보존)

- [ ] §D 오픈 이슈 표의 모든 행에 *담당자* + *기한* 명시 (CLAUDE.md §7)

### 점수 해석 (§A)

| 결과 | 처리 |
|------|------|
| 자동 실패 0 위배 + 7/7 | 즉시 후행 영역 *완성 산출물 사용 게이트* 통과 |
| 자동 실패 0 위배 + 6/7 | 통과 — 미달 1항목을 §D 오픈 이슈로 이동 |
| 자동 실패 1건 이상 | 통과율 무관 재작성 1회 |
| 자동 실패 0 + 5/7 이하 | 재작성 1회 (3회 연속 미달 시 CLAUDE.md §10 재시도 한계) |

**※ 자가점검 통과 = 완성 검증** (§4-0 (iv) 정합). 후행 영역(TR·UX·P) 진입 트리거 *아님* — 후행은 부분 broadcast마다 즉시 진행. 후행이 *완성된 산출물로 사용*하는 시점에만 본 게이트 적용 (CLAUDE.md §6-2).

## §B. M11 v1 cross-ref 자가 점검 (M9 §10-2-2 — 보존 + 정규식 4 segment 갱신)

### 결과 형식 — 8필드 (M9 §9-4 F-7 통합 — 보존)

각 §B 항목 결과를 다음 8필드로 `_broadcast.log`에 type=`self-check`로 기록:

| # | 필드 | 의미 |
|---|------|------|
| 1 | `type` | `self-check` |
| 2 | `timestamp` | 시점 |
| 3 | `owner` | `REQ` (M16 owner enum) |
| 4 | `target` | `01-prd.md` |
| 5 | 위반 항목 ID | F-* / M-* / U-* / H-* |
| 6 | `result` | `pass` / `warning_only` / `error` |
| 7 | `사유` | 1~3 문장 |
| 8 | `evidence_ref` | grep·라인·파일 |

### Part 1 — REQ owner 자동 도출 (M9 line 1740 — 정규식 4 segment 갱신, PI-004)

- [ ] **F-1·F-2·F-3** (REQ 한정): ID 정합 — 영역별 독립 시퀀스 max(NNN)+1, 중복·재사용 없음. 결번은 허용 (M9 §1-2-2). **정규식**: `^REQ-[A-Z]{2,4}-\d{3}-\d{2}$`
- [ ] **F-4·F-5·F-6** (REQ 한정): 헤더 정합 — §B 대분류 그룹화 (`### §B-N {대분류명}`) 안에 요구사항 헤더 `#### REQ-{도메인}-NNN-NN ({요구사항명})` 형식 일치 (template 구조 정합)
- [ ] **F-8** (REQ 한정): NA 사유 누락 검증 (NA 항목 시 사유 1줄 강제)
- [ ] **M-a** (REQ 영역): orphan 없음 — PRD에 정의된 REQ가 후행 영역에서 미참조되지 않음
- [ ] **M-d** (REQ 영역): deprecated 참조 없음 — deprecated REQ를 active 영역이 참조하지 않음

### 전 owner 공통 (M9 line 1744)

- [ ] **H-1·H-2·H-5** NA 휴리스틱 — NA 항목 시 적용, 없으면 N/A 명시

### Part 2 — 범용 U-1~U-5 (M9 line 1748~1754)

- [ ] **U-1**: M9-5 자동 검증 통과 (`_broadcast.log` REQ 영역 error 0건)
- [ ] **U-2**: Decision Log 변경 사항 반영 (STATE.md 기록)
- [ ] **U-3**: 후행 영역(TR·UX·P) broadcast 발행 확인 (Mesh 5요소 §4-0 (ii))
- [ ] **U-4**: 노션 동기화 대상 결정 (PM 승인 — `/sync-notion` 시점)
- [ ] **U-5**: 본 §B 결과를 `_broadcast.log`에 8필드 기록 (evidence)

### 통과 기준 (§B)

- error 0건 → 통과
- error 1건 이상 → remediation Task 신설, Gate B 차단 (M9 §10-2-3)
