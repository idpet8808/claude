# ux-spec — UX 화면 명세서 작성 Skill

## 언제 쓰나
- UX기획자가 PRD + 기술 검토서를 받아 화면 단위로 명세서를 작성할 때
- **선행 조건 (둘 다 필수)**:
  - `projects/<slug>/01-prd.md` 존재
  - `projects/<slug>/02-tech-review.md` 존재 (자가 점검 ≥ 4/5)

## 호출 절차

1. **세 파일 읽기** (first read)
   - `STATE.md` — 현재 단계·오픈 이슈
   - `01-prd.md` — Must 기능, 1차 사용자, 시나리오
   - `02-tech-review.md` — 기술 제약, "조건부/불가능" 기능

2. **기술검토 제약 반영**
   - 검토서의 "조건부" 기능은 대안 경로를 화면에 명시
   - 검토서의 "불가능" 기능은 화면에서 **완전히 제외**
   - PRD Must 수 = 화면 명세의 주요 플로우 수와 정합되어야 함

3. **template.md 로드 → 화면 단위 명세 작성**
   - **화면 목록 표** 먼저 (진입 경로 / 주요 컴포넌트 포함)
   - 각 화면별 4가지 상태 필수: **정상 / 빈 상태 / 에러 상태 / 로딩 상태**
   - 인터랙션: 트리거 / 동작 / 결과 상태 3요소
   - 비주얼 디자인(색상·폰트)은 **작성 금지** (CLAUDE.md §5 영역 침범)

4. **checklist.md 로드 → 4개 항목 자가 점검**
   - **빈/에러/로딩 상태 누락 시 자동 실패** (재작성)
   - 통과율 < 75% (3/4 미만)이면 재작성

5. **STATE.md 갱신**
   - 산출물 인덱스: `- [x] 03-ux-spec.md (YYYY-MM-DD)`
   - Decision Log: 기술검토 제약으로 제외한 기능 기록
   - 마지막 업데이트 갱신

## 출력 경로
- `projects/<slug>/03-ux-spec.md` (고정)

## 완료 보고 형식
```
[UX기획자] 완료
- 산출물: projects/<slug>/03-ux-spec.md
- 자가 점검: N/4
- 오픈 이슈: N건
- 다음 권장: 노션관리자 호출 (산출물 동기화)
```

## 참조 파일
- `template.md` — 화면 명세서 구조 템플릿
- `checklist.md` — 4개 자가 점검 항목
