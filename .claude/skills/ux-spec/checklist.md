# UX 화면 명세서 자가 점검 체크리스트 (M16 — PI-001~PI-019 정합)

UX기획자가 명세서 작성 직후 1차 게이트, 팀장 Claude가 후행 영역(P) *완성 산출물 사용 게이트* 진입 시 2차 게이트로 사용.

산출물 본질(§A 자동 실패 3건 + 통과율 4건) + cross-ref 정합(§B M11 v1 — 보존 + 정규식 갱신) 두 layer.

**통과 기준**: §A 자동 실패 0 위배 + 통과율 ≥ 3/4 + §B error 0 (CLAUDE.md §6-2 정합).

---

## §A. 산출물 본질 자가 점검 (M16 PI 정합)

### 자동 실패 조건 (3건 — 1건 위배 시 통과율 무관 즉시 재작성)

#### A-1. 화면 메타 7 필드 누락 0건 (PI-019 — BN 표준 양식)

- [ ] 모든 화면이 메타 헤더 7 필드 채움
- **메타 7 필드**: 버전(ver) / 화면명(한글) / Screen ID (UI-{명칭}-{NN}) / 이용자(PC/모바일) / 작성인 / 작성일 / 페이지 경로
- **자동 실패 사유**: BN 표준 양식 본질. 메타 누락 시 퍼블 전달 자료 부재

#### A-2. Screen ID 정규식 정합 (PI-019 — ID 체계 본질)

- [ ] 모든 Screen ID가 정규식 `^UI-[A-Za-z][A-Za-z0-9_]*-\d{2}$` 정합
- **형식**: `UI-{명칭}-{NN}` (영문 + Underscore 단어 결합 + 2자리 시퀀스)
- **예시**: `UI-Header_Footer-00`, `UI-Login-01`, `UI-Member_List-02`
- **자동 실패 사유**: ID 체계 본질. 정규식 위배 시 cross-ref·후행 매핑 깨짐. *S-NNN 형식 폐기* (PI-019)

#### A-3. 4상태 (정상/빈/에러/로딩) 모두 정의 (M9·M13 보존 + M18 갱신)

- [ ] 각 화면 섹션에 **정상 / 빈 / 에러 / 로딩** 4개 하위 상태 모두 정의
- **정상**: HTML wireframe (`04-prototype-mvp/pages/<UI>.html`) 시각 표현
- **빈/에러/로딩**: 03-ux-spec.md 텍스트 명세 (마크다운 리스트)
- **자동 실패 사유**: 화면 명세 본질. 누락 시 후행(퍼블) 작업 불가능

---

### 통과율 산정 4항목 (3/4 이상 통과, 2/4 이하 재작성)

#### B-1. 시각적 스켈레톤 와이어프레임 존재 (M16 격차 7 정정 + M18 갱신)

- [ ] 모든 화면이 **HTML wireframe** (`04-prototype-mvp/pages/<UI-{명칭}-{NN}>.html`) 파일 존재
- [ ] HTML 상단 SSoT 주석 정합 (정규식: `^<!-- UI-[A-Za-z][A-Za-z0-9_]*-\d{2} / → REQ-[A-Z]{2,4}-\d{3}-\d{2}(, REQ-[A-Z]{2,4}-\d{3}-\d{2})* -->$` 또는 전역 `^<!-- UI-[A-Za-z][A-Za-z0-9_]*-\d{2} / → 전역 -->$`)
- [ ] 영역 번호 마커 `<span class="area-num">N</span>` 존재 + 03-ux-spec.md Description §N과 1:1 매핑
- 스켈레톤 = 화면 *구조* (블록·placeholder·영역 번호). 비주얼 디자인 시안 X (색상·폰트·세부)
- ASCII/Unicode 박스만 (HTML wireframe 부재) = *부정합* (M18 격차 회귀)

#### B-2. Description (영역별 번호 + 동작·연결 페이지) 정합 — M16 PI-019 + M18 갱신

- [ ] 03-ux-spec.md Description = 마크다운 표 형식 (영역 번호 \| 내용)
- [ ] HTML wireframe `<span class="area-num">N</span>` 마커와 .md Description §N **1:1 매핑** (자동 검증 대상)
- [ ] 각 번호별 *설명* + *구성 요소 정의* + *동작* + *연결 페이지* 명시
- 예: `**3** \| **계정 및 기업 정보 확인 영역**<br>- 3-1. 아이디: 입력 필드 / 텍스트 입력 / 필수 (*) / 중복 아이디 사용 불가`

#### B-3. 요구사항 ID 1:1 매핑 (PI-001·PI-002·PI-003·PI-004 갱신)

- [ ] 화면 헤더 형식 (REQ 매핑 화면): `### UI-{명칭}-{NN} (→ REQ-{도메인}-NNN-NN, ...)`
- [ ] **전역 화면 예외** (헤더/푸터 등 REQ 무관 공통 레이아웃): `### UI-{명칭}-{NN} (→ 전역 공통)` 형식 허용
- [ ] 모든 *REQ 매핑 화면*이 PRD §B 카탈로그 REQ ID 매핑 (1 화면 ↔ N REQ 가능). 전역 화면은 예외
- [ ] PRD §B Must·Should 카탈로그 누락 화면 0건 (전수 매핑 — 전역 화면 N/A)
- *PRD Must 정합* (M9·M13) 폐기 — *요구사항 ID 1:1 매핑* 본질
- 참조 형식: `01-prd.md §B-N REQ-{도메인}-NNN-NN` (전역 화면 N/A)

#### B-4. 기술검토 제약 처리 (M9·M13 보존)

- [ ] 02-tech-review.md §2 판정 기준:
  - **불가능** REQ → 화면에서 **제외**
  - **조건부** REQ → 화면에 **대안 경로** 또는 **조건 명시**

### 점수 해석 (§A)

| 결과 | 처리 |
|------|------|
| 자동 실패 0 위배 + 4/4 | 즉시 후행 영역(P) *완성 산출물 사용 게이트* 통과 |
| 자동 실패 0 위배 + 3/4 | 통과 — 미달 1항목을 §6 오픈 이슈로 이동 |
| 자동 실패 1건 이상 | 통과율 무관 재작성 1회 |
| 자동 실패 0 + 2/4 이하 | 재작성 1회 (3회 연속 미달 시 CLAUDE.md §10) |

⚠️ **자가점검 통과 = 완성 검증** (§4-0 (iv) 정합). 후행 영역(P) 진입 트리거 *아님* — 후행은 부분 broadcast마다 즉시 진행.

## §B. M11 v1 cross-ref 자가 점검 (M9 §10-2-2 — 보존 + 정규식 갱신)

### 결과 형식 — 8필드 (M9 §9-4 F-7)

| # | 필드 | 값 |
|---|------|-----|
| 1 | type | self-check |
| 2 | timestamp | YYYY-MM-DD |
| 3 | owner | `UX` (M16 owner enum) |
| 4 | target | 03-ux-spec.md / UI-{명칭}-{NN} |
| 5 | 위반 항목 ID | F-* / M-* / U-* / H-* |
| 6 | result | pass / warning_only / error |
| 7 | 사유 | 1~3 문장 |
| 8 | evidence_ref | grep·라인·파일 |

### Part 1 — UX owner 자동 도출 (M9 line 1742 — 정규식 갱신, PI-019)

- [ ] **F-1·F-2·F-3·F-4·F-5·F-6** (UX 한정): ID 정합 + 헤더 정합. **Screen ID 정규식**: `^UI-[A-Za-z][A-Za-z0-9_]*-\d{2}$`. 헤더 형식 (REQ 매핑): `### UI-{명칭}-{NN} (→ REQ-{도메인}-NNN-NN, ...)`. 헤더 형식 (전역 화면 예외): `### UI-{명칭}-{NN} (→ 전역 공통)`. 결번 허용 (M10 §1-2-2)
- [ ] **F-8** (UX 한정): NA 사유 누락 검증
- [ ] **M-b·M-c·M-e** (UX 영역): 출처/끊김/NA 모순 없음. *REQ 매핑 화면*은 PRD §B REQ ID 참조 + 참조 REQ 실제 존재. *전역 화면*(`→ 전역 공통`)은 M-b·M-c REQ 매핑 검증 N/A (UI ID 매핑만 검증)
- **REQ 매핑 정규식**: `^REQ-[A-Z]{2,4}-\d{3}-\d{2}$` (PI-004)

### 전 owner 공통 (M9 line 1744)

- [ ] **H-1·H-2·H-5** NA 휴리스틱 (NA 시 적용, 없으면 N/A)

### Part 2 — 범용 U-1~U-5

- [ ] **U-1**: M9-5 자동 검증 통과 (UX 영역 error 0)
- [ ] **U-2**: Decision Log 변경 사항 반영 (기술 제약 처리·접근성 결정 등)
- [ ] **U-3**: 후행 영역(P) broadcast 발행 확인 (Mesh 5요소 §4-0 (ii))
- [ ] **U-4**: 노션 동기화 대상 결정 (PM 승인)
- [ ] **U-5**: 결과 `_broadcast.log` 8필드 기록 + **broadcast 발행 시 SendMessage 동시 발행 evidence 확보** (M17 PI-023 — 격차 C 정정 — 양쪽 의무)

### 통과 기준 (§B)
