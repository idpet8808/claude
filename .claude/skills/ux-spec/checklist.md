# UX 화면 명세서 자가 점검 체크리스트 (4항목)

UX기획자가 명세서 작성 직후 1차 게이트, 팀장 Claude가 노션관리자 호출 전 2차 게이트로 사용.
통과 기준: **3/4 이상 (75%)**. CLAUDE.md §5 엄격 기준 적용 시 **4/4 필수**.

---

## 1. PRD Must 수와 화면 명세의 주요 플로우 수가 정합하는가?
- [ ] PRD `4. Must` 기능 수 ≤ 화면 명세 `1. 화면 목록`의 주요 플로우 수
- **실패 예**: Must 5개인데 화면 3개만 설계 → 2개 기능이 어디서 쓰이는지 불명
- **이유**: Must 기능 하나는 최소 1개 화면에 매핑되어야 함

## 2. 모든 화면에 빈/에러/로딩 상태 4가지가 정의되어 있는가?
- [ ] 각 화면 섹션에 **정상 / 빈 / 에러 / 로딩** 4개 하위 섹션이 모두 존재
- **실패 시 자동 0점** (이 항목은 누락 용인 불가)
- **이유**: 빈·에러·로딩은 개발 단계에서 가장 자주 빠지는 구멍. UX 단계에서 반드시 명시해야 함

## 3. 모든 화면에 진입 경로가 명시되어 있는가?
- [ ] 각 화면 섹션의 **진입 경로** 필드가 비어있지 않음
- **실패 예**: "어디서 들어오는지 미정"
- **이유**: 진입 경로 없이는 네비게이션 플로우를 그릴 수 없고, 개발자가 라우팅을 설계할 수 없음

## 4. 기술검토 "조건부/불가능" 항목이 화면에서 올바르게 처리되었는가?
- [ ] `02-tech-review.md §2` 판정 기준으로:
  - **불가능** 기능 → 화면에서 **제외**
  - **조건부** 기능 → 화면에 **대안 경로** 또는 **조건 명시**
- **실패 예**: 기술검토서가 "실시간 알림 불가능"으로 판정했는데 화면 명세에는 실시간 알림 포함
- **이유**: 기술 제약을 무시한 UX는 개발 단계에서 스프린트 폭파의 주범

---

## 점수 해석
- **4/4**: 즉시 노션관리자 호출 가능
- **3/4**: 통과하되, 미달 항목을 오픈 이슈로 이동 후 호출
- **2/4 이하**: 재작성 필수
- **빈·에러·로딩 상태 누락**: 점수와 무관하게 재작성 필수 (항목 2)
