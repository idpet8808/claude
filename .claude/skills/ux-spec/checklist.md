# UX 화면 명세서 자가 점검 체크리스트 (M11 v1 — M9 §10-2-2 정합)

UX기획자가 명세서 작성 직후 1차 게이트, 팀장 Claude가 퍼블리셔 호출 전 2차 게이트로 사용.

산출물 품질(§A 4항목) + cross-ref 정합(§B M11 v1) 두 layer.

통과 기준: **§A 3/4 이상 + §B error 0 + 빈/에러/로딩 자동 실패 없음**.

---

## §A. 산출물 품질 자가 점검 (4항목, 통과 3/4)

### 1. PRD Must 수와 화면 명세의 주요 플로우 수가 정합하는가?
- [ ] PRD `4. Must` 기능 수 ≤ 화면 명세 `1. 화면 목록`의 주요 플로우 수

### 2. 모든 화면에 빈/에러/로딩 상태 4가지가 정의되어 있는가? ⚠ 자동 실패 조건
- [ ] 각 화면 섹션에 **정상 / 빈 / 에러 / 로딩** 4개 하위 섹션이 모두 존재
- **누락 시 통과율 무관 자동 실패** → 즉시 재작성

### 3. 모든 화면에 진입 경로가 명시되어 있는가?
- [ ] 각 화면 섹션의 **진입 경로** 필드가 비어있지 않음

### 4. 기술검토 "조건부/불가능" 항목이 화면에서 올바르게 처리되었는가?
- [ ] 02-tech-review §2 판정 기준으로:
  - **불가능** 기능 → 화면에서 **제외**
  - **조건부** 기능 → 화면에 **대안 경로** 또는 **조건 명시**

### 점수 해석 (§A)
- **4/4**: 퍼블리셔 호출 가능
- **3/4**: 통과 — 미달 항목 오픈 이슈
- **2/4 이하**: 재작성 필수
- **빈/에러/로딩 누락**: 점수 무관 재작성 필수 (자동 실패)

## §B. M11 v1 cross-ref 자가 점검 (M9 §10-2-2)

### 결과 형식 — 8필드 (M9 §9-4 F-7)

| # | 필드 | 값 |
|---|------|-----|
| 1 | type | self-check |
| 2 | timestamp | YYYY-MM-DD |
| 3 | owner | UX기획자 |
| 4 | target | 03-ux-spec.md / S-NNN |
| 5 | 위반 항목 ID | F-* / M-* / U-* / H-* |
| 6 | result | pass / warning_only / error |
| 7 | 사유 | 1~3 문장 |
| 8 | evidence_ref | grep·라인·파일 |

### Part 1 — S owner 자동 도출 (M9 line 1742)

- [ ] **F-1·F-2·F-3·F-4·F-5·F-6** (S 한정): ID 정합 + 헤더 정합. S-NNN 영역별 독립 시퀀스, 헤더 형식 `## S-NNN (→ REQ-XXX, REQ-YYY)`. 결번 허용 (M9 §1-2-2)
- [ ] **F-8** (S 한정): NA 사유 누락 검증
- [ ] **M-b·M-c·M-e** (S 영역): 출처/끊김/NA 모순 없음. 모든 S-NNN이 PRD REQ 참조 + 참조 REQ 실제 존재

### 전 owner 공통 (M9 line 1744)

- [ ] **H-1·H-2·H-5** NA 휴리스틱 (NA 시 적용, 없으면 N/A)

### Part 2 — 범용 U-1~U-5

- [ ] **U-1**: M9-5 자동 검증 통과 (S 영역 error 0)
- [ ] **U-2**: Decision Log 변경 사항 반영 (기술 제약 처리·접근성 결정 등)
- [ ] **U-3**: 후행 영역(P) broadcast 발행 확인 — **S 확정 broadcast 필수** (M9-2-c-4)
- [ ] **U-4**: 노션 동기화 대상 결정 (PM 승인)
- [ ] **U-5**: 결과 `_broadcast.log` 8필드 기록

### 통과 기준 (§B)
- error 0 → 통과 / error 1+ → remediation 신설, Gate B 차단
