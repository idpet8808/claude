## 리뷰 초점 (3축)

### 축 1 — 스킵 결정의 타당성 (필수)

5개 근거가 **실제로 성립**하는지, 반례·누락 시나리오가 있는지 검증.

- 근거 1 (YAGNI): 현 시점 실수요 부재 주장이 맞나. BN시스템 도메인(IT 기획·납품) 특성상 docx/pdf/hwpx 수요가 **예측 가능한 단기 미래**에 발생할 가능성은? 그 경우 지금 설계 보류가 합리적인가 vs 조기 투자가 유리한가
- 근거 2 (대체 경로): md 직접 파싱으로 cross-ref 감지가 실제로 동등한가. html 앵커 구조 없이 md 라인·정규식 의존 시 M9-5 구현 복잡도가 오히려 증가할 가능성은?
- 근거 3 (미래 확장성): "md canonical 정책 자체가 모든 미래 포맷에 열려 있음"이 실증 가능한 주장인가, 아니면 수사적 낙관인가
- 근거 4 (M9-5 선결 조건 아님): M9-5 cross-ref 스코프에서 html 부재로 발생하는 제약(예: 브라우저 기반 시각 감지 불가)을 PM이 인지·수용했는가
- 근거 5 (원 로드맵 전제 소멸): docx/pdf/hwpx 스코프 축소가 정식 결정인지, Q1 대화 중 잠정 선택을 과해석한 건 아닌지

### 축 2 — P1~P3 원칙의 완전성

실수요 발생 시점에 "원칙 부재로 재혼선"을 막기 위한 최소 원칙이라 했다. 그런데 **빠진 것**이 있는가?

- **누락 후보 1**: 변환 방향성 — P1이 "편집은 md에만"을 명시하나, **파생물 삭제·재생성 권한**은 누구인가(owner? 팀장? 별도 트리거?)
- **누락 후보 2**: 파생물 버전 추적 — M9-3의 `_broadcast.log`·Decision Log가 **md 기준**. 파생물 재생성 이벤트는 `_broadcast.log`에 기록 대상인가, 별도 로그인가, 무로그인가
- **누락 후보 3**: 파생물 저장 위치 — P2가 "보존 기법은 실수요 시 재논의"라 했으나 **저장 경로 규약**도 실수요 시 논의 대상인지, 아니면 본 M9-4에서 최소 가이드(예: `projects/<slug>/_derived/`)를 찍어야 하는지
- **누락 후보 4**: 스킵 결정의 재논의 트리거 — "실수요 발생 시 재논의"라 했으나, **무엇이 실수요인지** 판단 기준이 공백. owner 주관 vs PM 승인 vs 외부 고객 요청 등 재개 조건 명시 필요성
- **누락 후보 5**: P2 "손실 금지 원칙은 불변"이 강한 규범인데, 검증 주체·검증 시점이 없음. 향후 실수요 시 파이프라인 구현자가 이 원칙을 **어떻게 증명**할지 가이드 공백

### 축 3 — 선행 M 정합

M9-4 스킵 결정이 기존 확정 M 결정을 깨트리지 않는지:

- **M1** (역할 5명·산출물 1:1): 파생물 도입 보류가 M1 역할 구조에 영향 없는지 재확인
- **M2-5 Task evidence, M2-6 Gate B**: 산출물 생성 = md 파일 생성으로 충분한지 (파생물 없어도 Task 완료 가능)
- **M4-2 8-event closed set**: 파생물 생성·재생성이 이벤트 체계 밖에 있는 것이 일관성 확보되는가
- **M6 파일 소유권 정적 1:1**: owner 정의에서 파생물 권한이 누락되어도 무방한가 (스킵이므로 파생물 없음 → 무쟁점?)
- **M9-1 §1-7 정합 보강**: "포맷 변환 → M9-4" 취소선 처리가 §1-7 다른 항목 (M9-2-b ✅ 패턴)과 형식 일치하는가
- **M9-2/M9-3 불변식 I1~I14**: §8 P2가 "보존 필수"로 I14(ID 불변) 강화하는 구조이나, 보존 기법 미정 상태에서 I14 강화 효과가 실질적인가
- **CLAUDE.md §3 Gate 구조**: 스킵 결정도 Gate A 대상인지 — 본 리뷰는 advisory로 진행 중이나 스킵도 "설계 결정"으로 봐야 하는가에 대한 PM 안전성 판단 타당
